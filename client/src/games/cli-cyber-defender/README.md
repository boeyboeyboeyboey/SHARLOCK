# CLI Cyber Defender — client module

Browser half of the `cli-cyber-defender` game (G-CLI), served at `/games/cli-cyber-defender` from the existing `cottage` building at (112, 112). Scoring and timing live on the server; see `server/src/modules/games/cli-cyber-defender/README.md`.

## Presentation summary

- **What:** a timed terminal game (ruleset `cli-3`). An alert describes the behaviour and lists suspects but never names the culprit, so investigate first with the fictional lookups `logs <host>` and `whois <ip>` (6 per challenge, no score), then act with `block ip`, `disable user` or `isolate host`. About two challenges per shift are false alarms answered with `dismiss`, and the two hardest need two ordered actions. Eight challenges, maximum 2,700 points.
- **Concept taught:** incident triage and containment (firewall blocking, account security, host isolation) with CIA-triad and attack-stage tags in every debrief; nothing real is ever executed.
- **Chooser:** the first screen is labelled "Save this run to" with **Start the run** as its button. The debrief shows "Next run: <destination> · <Timed|Practice>" and a **Change** button to pick another class or mode before **Play again**.
- **How to play:** choose where to save the run (personal or a class), then **Start game** (20-30 seconds per challenge, 2 pauses of 30 seconds in total; a wrong action or dismiss costs 5 seconds, shown as a brief "-5 s" cue in the Window tile and as a terminal line) or **Practice** (no timer, no time penalty, two hint tiers per incident: Hint names the evidence line and a lookup to run that never targets the culprit, then Hint 2 explains the concept and command family without naming the target, and on a false alarm without giving the verdict; neither hint is scored and the debrief marks hinted incidents "hint used"). Tap alert names or command templates on touch screens; this fills the prompt without raising the on-screen keyboard, and you tap the input to type.
- **How to play guide:** a shared `HowToPlayDialog` opens on the first visit and from the **How to play** button above the chooser, until the player ticks the dismiss box. It shows four steps (investigate, act, keep the streak, debrief) beside a looping `DemoTerminal` and a caption per step, plus the learning point, rules and controls from `howToPlay.js`.
- **Technical points:** `CliDefenderGame.vue` → `useCliDefender.js` → `cliDefender.js`. Runs need a signed-in session and CSRF (via the shared `writeAttempt`); the server owns the timing and score. The shared `AttemptContextChooser` supplies the run context.
- **Saved runs:** a finished timed shift or a practice run is saved as an attempt on `/complete`; the debrief shows "Result saved to your account." or the save error with **Try saving again**. Timed class runs rank on the class Best board (Timed runs); practice counts toward the all-time view.
- **Status and limits:** record in TASKS.md (SAVE-CLI). Runs live in server memory with a 10-minute idle expiry (an hour for a paused run or a failed save), so an abandoned run is never saved; a reload or browser Back during a game asks first because the run cannot be resumed. Rankings are practice evidence, not validated mastery.

## Data flow

`CliDefenderGame.vue` → `useCliDefender.js` → `cliDefender.js` (shared `services/api.js`) → Express router → service → in-memory run.

1. `BriefingPanel` first shows `AttemptContextChooser` (personal or a class), then states the player's role, offers **Start game** (confirmed in a "Ready to play?" `ConfirmDialog`) or **Practice (no timer)**, and plays `DemoTerminal` with the command and scoring lists below those buttons. Its numbers come from `SHIFT_FACTS` in `cliDefender.js`, which a unit test compares with the server's `policy.js`. Starting emits `start(mode, context)` and the composable posts `{ mode, context }`, creates a run and prints the first challenge.
2. The player types a command, taps a command template, or taps a name in the alert to fill in the target. `help`, `history` and `clear` stay in the browser; everything else (lookups, actions and `dismiss`) is posted with a fresh `actionId`. Lookup results print inline in amber under `[logs host] (n/6)`; the 7th returns the server's limit message; a first correct step of a two-step incident prints `[STEP]` and the banner shows "Step 1 done, the incident is still open" without revealing how many steps there are. Enter is ignored while a command is in flight.
3. A 100ms interval only refreshes the displayed countdown from the server deadline, corrected by `serverNow`. When a window reaches zero, or the tab becomes visible again, the composable fetches a fresh snapshot instead of counting ticks. A failed fetch retries after 1 s, doubling to 10 s; a 401 or 404 stops the interval and shows the message once.
4. After each closed challenge the terminal and `ReviewNote` show the correct command, why, and concept tags; `useCliDefender({ onEvent })` reports `alert`, `ok`, `fail` and `miss` so the screen can play `useCliSound` beeps, a keyed flash/stamp overlay and a shake.
5. In a timed game, hiding the tab or choosing **Pause** in `GameMenu` freezes the server clock, within a budget of 2 pauses and 30 seconds in total. `PausedPanel` covers the full-size console (the alert and terminal stay mounted but hidden and inert) and counts the budget down until **Resume game**; at zero the game resumes by itself. With no pause left the menu says so, and a hidden tab or the leave dialog no longer stops the clock. Practice never pauses.
6. **Quit to briefing** in the game's **Options** menu confirms that points won't be saved and returns to the briefing; the dialog opens on **Keep playing**, and in a timed game the clock is held while it is open. Holding it spends none of the player's 2 pauses: it has its own fixed total of 30 seconds per game, and once that is used up the dialog says the clock is running. The shared top bar's **Exit game** leaves for the town through its own dialog, which holds a timed clock the same way through `useInteriorLeave`, from the same fixed total, shows the same note, and restarts it on **Keep playing**. Browser Back during a game opens the same "Leave this game?" dialog through `onBeforeRouteLeave`, and a reload or closed tab raises the browser's own warning (`beforeunload`). **End practice** finishes a practice game early; its debrief lists only the incidents reached (the one on screen shows as NOT ANSWERED) and "Contained" counts out of those.
7. When no challenge remains, the composable requests the debrief. `ShiftDebrief` shows summary tiles, a topic table and collapsible incidents; the result shows "Result saved to your account." or the server's `saveError` with **Try saving again** (`retrySave` calls `/complete` again); `ReplayChoice` shows "Next run: <destination> · <Timed|Practice>", preselected from the last run, and **Change** reveals a "Save this run to" select (personal plus active classes, loaded on first open, or at once when the last run was in a class, with loading, error-with-retry and empty states) and a Timed/Practice radio group. **Play again** emits `replay({ mode, context })` and starts at once with that choice (no "Ready to play?" dialog, because the summary is visible); the composable keeps the context in `runContext` and `start(mode)` without a context reuses it. **Main menu** returns to the briefing.

## Design and accessibility

The game uses the DESIGN.md game exception: an original green/amber-on-black terminal set in Silkscreen (headings, stats, stamps) and Azeret Mono (body and terminal text), both SIL Open Font License, self-hosted through `@fontsource/silkscreen` and `@fontsource/azeret-mono` (latin and latin-ext, 400 and 700, imported in `cli.css`; FONT-04, no Google Fonts at runtime) with a system monospace fallback and ligatures off. Every rule in `cli.css` is under `.cli-game` with `--game-*` variables; nothing targets `:root`, `body`, the navbar or another module. The town building, metadata card and shared pages keep the hub pixel scheme.

- Layout uses the Bootstrap grid (status tiles 2 then 4 columns from `md`; briefing lists side by side from `lg`; alert beside the terminal from `xl`). Container queries size the command templates, the prompt (`$` only when narrow) and the briefing lists by their own width, so labels never wrap mid-word. While a game runs (`is-playing`) the console fills one screen and never scrolls as a page: the alert column and the terminal log scroll inside themselves, the Hint row is pinned to the bottom of the alert, and the prompt and six command buttons stay in view. Below 1200px the alert sits above the terminal at no more than a third of the console and the command buttons form a 3 × 2 grid; on short windows and phones the game takes the screen below the shared header, with a compact two-per-row status bar and no Last incident note. Below 576px one screen is too small for both, so the page scrolls normally: the alert shows in full, the log is 10rem tall, the status bar stays pinned under the top bar so the clock stays visible, and each new alert scrolls back into view. On laptop-height windows the debrief keeps its summary and buttons fixed above a divider and only the incident list scrolls; on phones the debrief scrolls as one page.
- Bootstrap `.btn`, `.badge`, `.progress` and `.visually-hidden` are re-themed through their `--bs-*` variables under `.cli-game`; `.portal-shell .btn` has equal specificity, so the game styles win because `cli.css` loads after `main.css`.
- The terminal output is a `role="log"` live region; outcomes are written as `[ OK ]`, `[FAIL]`, `[MISS]` text and stamps, never colour alone. The countdown is hidden from assistive technology and the window length is announced once per challenge.
- `GameMenu` follows the menu-button pattern (`aria-haspopup`, arrow keys, Escape returns focus, outside click closes); `ConfirmDialog` uses the native modal so focus stays inside and Escape cancels. Staying after "Leave this game?" returns focus to the prompt, or to the log on a touch screen.
- Up/Down recall earlier commands; template, chip and menu targets are at least 34–48px tall; the input disables autocorrect and autocapitalisation.
- Animations (alert entry and typing, line fade-in, stamps, flash/shake, score count-up, icon pops, radar sweep, confetti, demo loop) are limited to moments that mean something, and reduced motion turns all of them off along with the scanlines. Sound is generated with Web Audio, off on every visit, and the context is closed on unmount.
- All requests are aborted and the interval, `visibilitychange` and outside-click listeners removed on unmount.
- The "-5 s" penalty cue is decorative (`aria-hidden`); a visually hidden `role="status"` line and the terminal log line carry the same message. The Window tile counts down to the server's `closesAt`, which already includes any penalty.
- On a coarse pointer nothing focuses the input for the player, so the on-screen keyboard rises only when they tap it; a real phone keyboard has not been tested.
- A signed-out request (401) shows "Your session ended. Sign in again to play."
