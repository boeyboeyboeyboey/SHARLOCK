# Game interiors (INT-01, INT-03, INT-04)

## Presentation summary

- What it is: a picture of the inside of each game's building on the 1880 Thames wharf, shown behind the game route with the game in a framed desk panel. This is atmosphere, not a security lesson, so it needs no course citations.
- How to use it: nothing to operate. Open a game from the hub or town; the still sits behind the centred desk.
- History: INT-01 drew each room live in Babylon; INT-03 (Boey, 1 November 2026) switched every device to a still because players could barely see the live room and it cost performance; INT-04 (Boey, 1 November 2026) removed the unused live-room code, its capture script and the 3D | 2D switch on game pages. The stills are Gemini images since ASSET-01. The old room code is in git history (before INT-04).
- Technical: `InteriorLayout.vue` is the parent route of the five game routes (`client/src/router/index.js`, `meta.interior` is the room id). It shows `/interiors/<id>.webp` over a gradient in the room palette, which stays visible if the image fails. Game routes load no Babylon code.
- Data: none stored.
- Status: see the INT-01, INT-03 and INT-04 records in [TASKS.md](../../../../TASKS.md).
- Known limits: a still is static (no ambient motion); a new still is made by hand from the prompts in [docs/asset-generation-guide.md](../../../../docs/asset-generation-guide.md) §2.

Owner: Boey. Integration-sensitive: the router (five game routes are children of the layout), `ImmersiveControls.vue` (`showMode` prop) and `--shell-chrome`, which the layout redefines on the desk panel only. Game modules are never edited.

## File map

- `InteriorLayout.vue`: stage (still over the palette gradient) plus the `<RouterView />` desk panel, sound, game chrome and the leave confirmation.
- `renderMode.js`: pure helpers `stillUrl(id)` and `fallbackGradient(palette)`.
- `rooms/palettes.js`: `palettes` and `roomFor(id)`, returning `{ palette }` (top, bottom and accent colours) or null.
- `useInteriorLeave.js`: optional hook for a game under this layout: `useInteriorLeave({ onOpen, onClose, note })` runs when the shared leave dialog opens and closes, so a timed game can hold its clock; `onClose` runs when the player stays or a confirmed leave's navigation fails, and the optional `note` ref adds a line to the dialog. CLI Cyber Defender uses it.
- `__tests__/`: unit and mount tests.

## Audio (AUDIO-04)

- Theme: `InteriorLayout.vue` calls `useGameAudio(() => roomId)` (`client/src/composables/useGameAudio.js`), which loops `/audio/games/<room id>-theme.mp3` through `useLandingMusic` (same autoplay, one-time `pointerdown`/`keydown`/`touchstart` fallback, shared session key `sharlock.musicMuted`, never persists "unmuted", cleanup on leave). The hub and town audio are not mounted on game routes, so the theme is the only music.
- Control: the round glass `interior-sound` button sits in the sound slot of the game chrome (below), first in the top right group. It is hidden when the theme file is missing or fails to decode (the composable holds playback and shows no message).
- Effects: `playSfx(name)` from `client/src/composables/playSfx.js` for `correct`, `wrong`, `win`, `lose` and `click` (`/audio/games/sfx-<name>.mp3`). It follows the shared mute, keeps a pool of two elements per name, drops a missing or undecodable file for the rest of the visit and never throws or logs. It does nothing under jsdom. Wired in the phishing, SQL, social and clearance game views; CLI keeps its own beeps.
- Files are generated by Boey; see [docs/asset-generation-guide.md](../../../../docs/asset-generation-guide.md). Everything works silently while they are absent.

## Game chrome and Exit (INT-02)

- Shell: the `/games` parent route has `meta.immersive`, so `PortalLayout.vue` drops the navbar and sidebar, and the footer is hidden when `meta.interior` is set. The layout sets `--header-height: 0` and clears the sidebar margin for its own screens. On phones and short touch landscapes it sets `--header-height` to the 64px top bar instead, so games that size themselves to the screen minus the header start below the bar (FIX-07).
- Controls: `InteriorLayout.vue` mounts `ImmersiveControls.vue` with `:show-mode="false"` (Menu with `SiteMenu`, `sound` slot, `end` slot with **Exit game**; no 3D | 2D switch since INT-04, because the room is always a still). `escape-ignore-within=".interior-desk"` keeps Escape for the game panel.
- Leaving: Exit game, and any site menu link, open `components/common/ConfirmDialog.vue` ("Leave the game?", Leave game / Keep playing; Escape cancels, focus returns to the opener). The menu guard is a flag set on the menu's `navigate` plus `onBeforeRouteLeave`, so the games' own links (for example Back to town) are never guarded. Sign out from the menu is not guarded.
- Space: a 60px `--top-band` above the desk keeps the controls clear of the panel; `--shell-chrome` is that band, the bottom room gap and the desk padding. On any window under 500px high the room shrinks to the 64px control bar and the desk's top padding to 8px (`--desk-pt`), so a game starts as high as this layout can put it. Getting a first-screen Start button above the fold at 667 x 375 still depends on each game's own content.

## Adding a room

1. Add the game id and its `[top, bottom, accent]` palette to `rooms/palettes.js`.
2. Give the game route `meta.interior` with that id under the `/games` parent in `client/src/router/index.js`.
3. Make the still from the guide's prompts and save it as `client/public/interiors/<id>.webp` (1600 x 900 WebP); without it the gradient shows.
