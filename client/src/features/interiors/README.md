# Game interiors (INT-01)

## Presentation summary

- What it is: a small 3D room behind each game route, the inside of that game's building on the 1880 Thames wharf, with the game framed as the room's working desk. This is atmosphere, not a security lesson, so it needs no course citations.
- How to use it: nothing to operate. Open a game from the hub or town; the room drifts slowly behind the panel. In 2D mode, without WebGL, on a slow device, on Low graphics or under reduced motion it is a still image or a single frame.
- Technical: `InteriorLayout.vue` is the parent route of the five game routes (`client/src/router/index.js`, `meta.interior` is the room id). `useInteriorEngine.js` starts a WebGL2 Babylon engine for one room; `renderMode.js` decides loop, single frame or still; `rooms/` holds one builder per room.
- Data: none stored; reads the Graphics setting, the stored town mode and the device check from the hub.
- Status: stages A to C (infrastructure, all five rooms and the 2D stills), see the INT-01 record in [TASKS.md](../../../../TASKS.md).
- Known limits: no shadows; WebGPU is not used; the room is not interactive; not verified on real phones or low-end hardware.

Owner: Boey. Integration-sensitive: the router (five game routes are children of the layout) and `--shell-chrome`, which the layout redefines on the desk panel only. Game modules are never edited.

## File map

- `InteriorLayout.vue`: stage (canvas, still or gradient) plus the `<RouterView />` desk panel. Chooses the render mode from `useTownMode` rules, the hub tier, reduced motion and a perf watch.
- `renderMode.js`: pure helpers `decideRender`, `roomBudget`, `stillUrl`, `fallbackGradient`.
- `useInteriorEngine.js`: `createInterior({ canvas, roomId, tier, renderMode })`; camera drift, render loop or single frame, full disposal. Dev only: `window.__interior` with `state.drawCalls`, `state.activeMeshes`, `mounts` and `disposals`.
- `rooms/index.js`: registry keyed by game id (`id`, `label`, `palette` of top, bottom and accent colours, lazy `load`).
- `rooms/index.js` entries and builders (each room is x right, y up, z away from the camera at the front wall):
  - `cli-cyber-defender`: `rooms/cli.js`, Telegraph Office instrument room (switchboard, wire map, relay rack, sounders, clerk).
  - `phishing-post-mortem`: `rooms/phishing.js`, Royal Mail Post Office sorting room (pigeonhole frame, counter with brass grille, scales, Dead Letter shelf, pillar box, dust motes, postmaster).
  - `sql-injection-arcade`: `rooms/sql.js`, H.M. Customs House bonded registry (ledger shelves, A-Z card cabinets with a sliding drawer, gate and badge booth, stencilled crates, swinging lamp, customs officer).
  - `social-engineering-simulator`: `rooms/social.js`, The Capybara & Crown snug (fireplace, booths, beer pumps, chalkboard, Private door, patron, publican).
  - `clearance-tower`: `rooms/clearance.js`, river-police records room (clearance-tab cabinets, document cage, role key board, four named desks, turning gears, pulsing lantern, policeman).
- `rooms/kit.js`: shared room pieces: `shell`, `hemi`, `lamp`, `labelAtlas` (one painted canvas of signs, uv per cell, no image files) and `resident` (hub capybara rig on desktop, static pose on compact and low).
- `__tests__/`: unit and mount tests.

## Audio (AUDIO-04)

- Theme: `InteriorLayout.vue` calls `useGameAudio(() => roomId)` (`client/src/composables/useGameAudio.js`), which loops `/audio/games/<room id>-theme.mp3` through `useLandingMusic` (same autoplay, one-time `pointerdown`/`keydown`/`touchstart` fallback, shared session key `sharlock.musicMuted`, never persists "unmuted", cleanup on leave). The hub and town audio are not mounted on game routes, so the theme is the only music. The layout registers the sound with the menu's sound registry, so Settings can toggle it too.
- Control: the round glass `interior-sound` button sits in the sound slot of the game chrome (below), first in the top right group. It is hidden when the theme file is missing or fails to decode (the composable holds playback and shows no message).
- Effects: `playSfx(name)` from `client/src/composables/playSfx.js` for `correct`, `wrong`, `win`, `lose` and `click` (`/audio/games/sfx-<name>.mp3`). It follows the shared mute, keeps a pool of two elements per name, drops a missing or undecodable file for the rest of the visit and never throws or logs. It does nothing under jsdom. Wired in the phishing, SQL, social and clearance game views; CLI keeps its own beeps.
- Files are generated by Boey; see [docs/asset-generation-guide.md](../../../../docs/asset-generation-guide.md). Everything works silently while they are absent.

## Game chrome and Exit (INT-02)

- Shell: the `/games` parent route has `meta.immersive`, so `PortalLayout.vue` drops the navbar and sidebar, and the footer is hidden when `meta.interior` is set. The layout sets `--header-height: 0` and clears the sidebar margin for its own screens.
- Controls: `InteriorLayout.vue` mounts `ImmersiveControls.vue` (Menu with `SiteMenu`, `sound` slot, 3D | 2D switch, `end` slot with **Exit game**). The switch overrides the stored town mode for this visit only (live room or still) and is locked when WebGL cannot start. `escape-ignore-within=".interior-desk"` keeps Escape for the game panel.
- Leaving: Exit game, and any site menu link, open `components/common/ConfirmDialog.vue` ("Leave the game?", Leave game / Keep playing; Escape cancels, focus returns to the opener). The menu guard is a flag set on the menu's `navigate` plus `onBeforeRouteLeave`, so the games' own links (for example Back to town) are never guarded. Sign out from the menu is not guarded.
- Space: a 60px `--top-band` above the desk keeps the controls clear of the panel; `--shell-chrome` is that band, the bottom room gap and the desk padding.

## Hero props (INT-02 stage 2a)

- A room can seat the game panel on one prop. Add `hero: { corners, camera }` to its `rooms/index.js` entry (data lives in `rooms/heroes.js`, free of babylon): `corners` are four world points `[x, y, z]` of the prop's usable surface in TL, TR, BR, BL order; `camera` is `{ pos, target, fov }` and replaces the room's own camera. A hero room has no camera drift, so the panel never lags its prop.
- `useInteriorEngine.js` projects the corners after the frame that follows each resize and calls `onHero(rect)`; `heroRect.js` (`rectFromCorners`, pure) takes the inscribed axis-aligned rect, grows it to 420 x 320 px at least and keeps it in the stage. `InteriorLayout.vue` positions `.interior-desk.is-hero` at that rect (hidden until the first rect), sets `--shell-chrome` so fitted games match the panel height, and drops the canvas blur and scale.
- Fallback: the centred desk is used with no hero, in the still or 2D mode, without WebGL (`heroActive`) and below 768px. The panel keeps its own scroll; a game depends on the rect only through its size.
- The prop must be drawn as a flat, camera-facing surface with its frame outside the corners, so the frame reads as the panel border. Phishing is the pilot (`inspectionBoard` in `rooms/phishing.js`); the other four rooms still use the centred desk. Regenerate the room's 2D still after changing its camera.

### Surface styles and blend (INT-02 stage 2b)

- A hero declares `surface: 'paper' | 'slate'` in `rooms/heroes.js` and the layout sets `data-surface` on the room. `InteriorLayout.vue` adds two layers around the desk panel at its rect: `.desk-surface` under it and `.desk-overlay` over it, both `pointer-events: none` and `aria-hidden`. The panel drops its own border and shadow, so the prop's brass lip is the edge.
- `paper` (light games): the surface layer is a paper tone with a grain texture, the panel itself uses `mix-blend-mode: multiply` so light game backgrounds take the paper tone and ink stays dark, and the overlay adds a soft lamp gradient and an edge vignette. Measured body text on the blended phishing panel is about 8.9:1.
- `slate` (dark games): a dark glass surface without multiply (it would crush to black), with a faint sheen, a warm lamp glow and a vignette in the overlay.
- All of it is static, so reduced motion needs nothing. The 2D still, no WebGL, phones under 768px and rooms without a hero keep the plain centred desk and render neither layer.
- `bleed: true` on a hero keeps the shell paddings instead of the compact hero ones, for a game that bleeds by the shell gutter (SQL injection arcade), so the game fills the panel edge to edge.
- Rooms with a hero (all five, stage 2c): phishing (inspection board, paper), CLI (operator's console with an "INSTRUMENT ROOM" plaque, sounder and key on the ledge, slate), SQL (registry ledger console with a "BONDED REGISTRY" plaque, dim room, pendant lamp over it, slate, `bleed`), social (the landlord's notice board with a "THE SNUG" plaque, message book, candles and a pint on the ledge, firelight lamp in front, paper), clearance (records case board with a "RECORDS" plaque, folders, nameplate and a banker's lamp on the ledge, cool lamp in front, paper). Social and clearance share the light green game background, so both use `paper`; neither bleeds. `rooms/kit.js` `heroBoard` draws the shared frame, face, rails and ledge.
- Stills: with every room on a hero camera there is no drift, so `scripts/capture-interiors.mjs` now captures in loop mode (no reduced motion; a single-frame canvas came out black) and also hides `.desk-surface` and `.desk-overlay`. The stills show the empty prop face; the 2D desk covers it.

## Budgets and tiers

Desktop: loop, resident NPC rig, at most 150 draw calls. Compact: loop, static NPC, at most 100. Low, or reduced motion: one frame, then the render loop stops (60 draw calls on Low). No shadows on any tier. The five rooms measure about 16 to 20 active meshes on desktop and 7 to 8 on compact and low.

## Adding a room

1. Create `rooms/<name>.js` exporting `(ctx) => { camera: { pos, target, fov, drift: [x, y, periodSec] }, update(dt, time), dispose() }`. `ctx` has `scene`, `engine`, `tier`, `budget` and `reduced()`. Reuse `rooms/kit.js` and build from `Batch` (hub `scenes/shared/geometry.js`), `toonMaterial` and `glowMaterial` (hub `scenes/wharf/toon.js`); merge static meshes and keep animated parts as small separate meshes.
2. Point the registry entry in `rooms/index.js` at it (`load: () => import('./<name>.js').then((m) => m.<builder>)`).
3. Add the id to `rooms` in `scripts/capture-interiors.mjs` and run it for the new still (see below); without a still the palette gradient is shown.
4. Add the room to the tests in `__tests__/renderMode.test.js` if it changes the registry shape.

## 2D stills

`client/public/interiors/<id>.webp` (1600 x 900, about 13 to 20 KB each) is shown in 2D mode, without WebGL and after a perf drop. The stills are rendered from the project's own Babylon rooms, not imported images. Regenerate them after changing a room, with the dev client and API running and a signed-in preview account (the script reads its credentials from `.local-handover/wardrobe-preview/login.txt`, which is gitignored, and never prints them):

```bash
node scripts/capture-interiors.mjs --base http://localhost:5176           # missing stills only
node scripts/capture-interiors.mjs --base http://localhost:5176 --force   # overwrite all
```

The script uses headless Chromium with the software renderer, the desktop tier, the live loop (no drift, since every room is a hero room) and the desk panel and its surface layers hidden, and encodes WebP through a canvas, so it needs no extra dependency. It is a developer tool and is not part of the build or the tests.
