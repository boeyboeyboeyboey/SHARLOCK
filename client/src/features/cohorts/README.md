# Class enrollment and management

## Presentation summary

- What it is: class enrolment and management: `/classes` (own memberships), `/join-class` (invitation or optional onboarding) and `/instructor` (requests, members and invitation codes for assigned classes).
- Security concept: access control by approved membership. A class code only creates a pending request; staff approve it, and the server re-checks role, assignment and membership on every request instead of trusting the browser. Codes are hashed server-side and expire after seven days. Course link: access control (07-access-control.pptx) in the [course reference index](../../../../TASKS.md#course-reference-index).
- Using it: a student enters the class code under "Class invitation code" and presses "Join class" (or skips); an assigned instructor or administrator opens `/instructor`, presses "Generate code" and later "Approve" or "Decline" under "Class access".
- Components: `JoinClassPage`, `MembershipsPage`, `ClassManagementPage`, `JoinCohortForm`, `MembershipList`, `EnrollmentQueue`, `EnrollmentCodePanel`; `api.js`, `journey.js` (code capture and routing after sign-in).
- API and data: calls the cohort endpoints in the [class API contract](../../../../server/src/modules/cohorts/README.md); codes are held in memory only and never written to browser storage.
- Status: see the COH-01 record in [TASKS.md](../../../../TASKS.md).
- Limits: a student holds at most one active or pending class (COH-04), so `/join-class` shows "You're already in <class>" with a link to Your classes instead of the form; enrolment writes need transaction-capable MongoDB; one reusable code per class; removal does not delete a student's completed results.

This feature connects account-first class invitations to the existing membership/access foundation. `/classes` lists only the signed-in learner's own memberships and offers Join a class later. `/join-class` handles a captured invitation or the one-time optional onboarding choice. `/instructor` is the existing staff preview route, replaced in place with assigned-class request, membership, and invitation-code controls. The selected class is kept in the address as `/instructor?class=<cohortId>`, so a reload or shared link reopens that class; an unknown or unassigned ID falls back to the first assigned class. The page updates the address with `history.replaceState` rather than a router navigation, so switching classes adds no history entries and the layout keeps focus and scroll position. The ID only preselects the dropdown; the server still authorizes every class request. `?view=results` switches the page to the Results panel (`client/src/features/class-results/ClassResults.vue`) using the same `replaceState` update; any other or absent `view` value shows the roster.

Class codes are normalized in memory and never written to browser storage. On a class-link visit, `captureInvitationCodeFromLocation()` synchronously reads and strips the fragment before session restoration or router installation. The caller then uses `prepareInvitation()` to place it in the server session; failed preparation retains only the in-memory code for retry. After account access, `resolveEnrollmentDestination(user)` checks the server's enrollment status and routes to the one-time invitation request or optional onboarding step. It does not alter auth DTOs or registration/login payloads.

All mutations fetch a fresh CSRF token and send one request. API errors map to fixed local messages. List and detail loads accept abort signals; mounted pages abort work and discard stale responses when selection changes or the view leaves. The code panel's Generate, Replace and Revoke buttons stay disabled while the selected class's code is loading. Membership states and inactive parent classes remain visible as supplied by the server; these client screens do not grant access or choose learning context.

Shared pages reuse the hub theme (Pixelify Sans headings, DotGothic16 body text), main.css palette and hard-shadow controls. `cohorts.css` contains rules to this feature's `.cohort-*` classes. No town camera, shared root token, navbar, or game module styles are changed.

Focused tests are in `__tests__/`; the guarded browser flow is `tests/e2e/cohorts.spec.js`. E2E setup must use the repository's disposable `_test` database runner and synthetic account fixture. No normal database or provider operation is part of this feature.
